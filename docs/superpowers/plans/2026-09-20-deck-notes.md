> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the pitch deck legible to someone who was not in the room: every card carries the spoken part of the pitch in a speech bubble, card 7 becomes the vision card, three small clarity fixes land, and the showcase site is rebuilt with it.

**Architecture:** The deck (`docs/duet/pitch/`) is one static HTML file, a CSS file, and a classic script whose pure functions hang off `window.Deck` for the Node tests. Each card is a CSS grid of three rows (header band, content, footer band); this plan adds an `<aside class="notes">` after the content, which takes an implicit fourth grid row when shown, holding a paper speech bubble, shown when the stage has the `shownotes` class (not `notes`: the asides' own hide rule `.notes { display: none }` would match a stage carrying that class and blank the deck) (on by default, `N` or the playbar's Notes pill toggles it, `?notes=0` starts hidden). Fixed photo heights shrink under `.stage.shownotes` so nothing overflows. The site's `presentation/` folder is a copy, regenerated by `site/build.py`.

**Tech Stack:** Vanilla HTML/CSS/JS, `node --test` for the deck tests (`code/hackathon/pagetests/pitch.test.mjs`), Python 3 for `site/build.py`, the built-in browser for the visual pass.
